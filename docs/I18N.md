# Internationalisation (i18n) — AmiPC

Ce document détaille la mise en œuvre de l'internationalisation, en complément de la section « 6. Internationalisation (i18n) » du [ROADMAP.md](../ROADMAP.md).

---

## 1. Système de Fichiers de Traduction

Le système repose sur trois fichiers JSON à la racine de `i18n/` :

- [i18n/fr.json](../i18n/fr.json) — Français (langue par défaut).
- [i18n/en.json](../i18n/en.json) — Anglais.
- [i18n/credits.json](../i18n/credits.json) — données structurées neutres (composants tiers), sans traduction car les noms de projets et licences ne se traduisent pas.

Ces fichiers sont déployés sur l'image cible dans `/data/i18n/` par le paquet Buildroot `amipc-init` (cf. `amipc-init.mk`).

## 2. Couverture des Traductions

| Écran / composant                    | Clé racine i18n | Statut |
|----------------------------------------|-------------------|--------|
| Écran « À propos »                     | `a_propos`         | Traduit FR/EN |
| Menu principal (displays, paramètres)  | `menu`             | Traduit FR/EN |
| Écran de paramètres (libellés fonctionnels) | `parametres`  | Traduit FR/EN |
| Layout principal (`layout.nut`)        | —                  | Aucun texte statique : uniquement des tokens dynamiques AttractMode (`[Title]`, `[Year]`, `[Manufacturer]`, `[FilterName]`) |

### Limite technique connue

Le formulaire natif de configuration d'un plugin AttractMode (bloc `UserConfig` de `config/attract/plugins/amipc_settings/plugin.nut`) est rendu directement par le moteur AttractMode (RGUI natif), qui ne dispose d'aucun mécanisme d'internationalisation pour ses propres écrans de configuration de plugin : les libellés de champ et les valeurs d'énumération (`Francais`/`English`, `Oui`/`Non`) y sont nécessairement fixes, quelle que soit la langue choisie ensuite dans l'interface AmiPC elle-même. Cette limite est propre au frontend AttractMode et ne peut être levée sans le patcher. Elle est documentée ici pour ne pas être confondue avec un oubli de traduction.

Tout le texte affiché à l'utilisateur en dehors de cet écran de configuration natif (écran « À propos », menu, libellés applicatifs) est exclusivement lu depuis les fichiers `.json`, sans chaîne codée en dur.

## 3. Sélecteur de Langue

Le sélecteur de langue est exposé dans le menu de configuration in-frontend (`amipc_settings`), champ `langue` (Francais / English). La sélection déclenche `amipc-set-langue`, qui met à jour `AMIPC_DEFAULT_LANG` dans `/etc/amipc/amipc.conf`, lu ensuite par tous les plugins (dont `amipc_about`) pour choisir le fichier `.json` à charger.

## 4. Langue par Défaut selon la Locale Système

Au premier démarrage de l'image (avant toute personnalisation utilisateur), le script `amipc-detecter-langue` (exécuté par `amipc-start` avant le lancement d'AttractMode) détecte la variable d'environnement `LANG` du système :

- `LANG` commençant par `en` → langue par défaut anglaise.
- Toute autre valeur (ou absente) → langue par défaut française.

Un marqueur (`/data/.amipc-langue-initialisee`) garantit que cette détection ne s'exécute qu'une seule fois, pour ne jamais écraser un choix explicite fait ensuite par l'utilisateur via le menu de configuration.

## 5. Vérification de l'Absence de Texte Codé en Dur

Audit réalisé sur l'ensemble des fichiers `.nut` du dépôt (thème et plugins AttractMode) :

- `themes/amipc/layout.nut` : aucun texte statique, uniquement des tokens dynamiques AttractMode.
- `config/attract/plugins/amipc_about/plugin.nut` : tous les libellés utilisateur proviennent de `i18n/*.json` (correction apportée : la liste des composants tiers est désormais extraite dynamiquement de `credits.json`, elle n'était initialement pas codée en dur mais figée en chaîne statique — corrigé pour rester synchronisé avec le fichier JSON).
- `config/attract/plugins/amipc_settings/plugin.nut` : les libellés du bloc `UserConfig` restent fixes pour la raison technique documentée en section 2 ci-dessus ; toute la logique d'application des choix ne contient aucun texte destiné à l'utilisateur final.
